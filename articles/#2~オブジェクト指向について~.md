## **ステップ 1: コードを読んで、問題点を探す**
やっと、実際にソースコードを記述し、開発を始めます。

環境構築が完了すると、以下のようなソースコードになっていると思います。

まず、元のソースコードを見て、改善すべき点を考えます。

```csharp:Program.cs
using DxLibDLL;

class Program {
    static void Main(string[] args) {
        // ウィンドウモードで起動するように設定
        DX.ChangeWindowMode(DX.TRUE);
        // Dxlib の初期化
        DX.DxLib_Init();
        // 描画先を裏画面に設定
        DX.SetDrawScreen(DX.DX_SCREEN_BACK);

        // メインループ
        while (DX.ProcessMessage() == 0) {
            // 画面をクリア
            DX.ClearDrawScreen();
            // 文字を描画
            DX.DrawString(100, 100, "Hello World", DX.GetColor(255, 255, 255));
            // 裏画面の内容を表画面に反映
            DX.ScreenFlip();
        }

        // Dxlib の終了処理
        DX.DxLib_End();
    }
}
```

このコードは問題なく動作しますが、改善できるポイントがいくつかあります。  

---

C#が持つ特性の1つであるオブジェクト指向を取り入れたコーディングを行いたいと思います。
オブジェクト指向とは、プレイヤー、コイン、地面、背景など、ゲーム内の各要素をクラスとして分割します。
オブジェクト指向を取り入れることで、新しい機能の追加や変更が容易になり、拡張性が向上します。
https://wa3.i-3-i.info/word1898.html

## **変更点 1: 初期化処理をまとめたい**
#### **(ここを変更したい！)**
`Main` メソッドの中に **初期化処理** (`ChangeWindowMode`, `DxLib_Init`, `SetDrawScreen`) がそのまま書かれています。  
これは **「プログラムの開始時にしか実行しない処理」** なので、別のメソッドにまとめたほうがコードがスッキリします。  

#### **(じゃあどうすればいいか？)**
新しく `Program` のコンストラクタを作成して、初期化処理をそこに移します。  

#### **(ソースコードの変更)**
```diff csharp:Program.cs
static class Program {
+     static Program() {
+         DX.ChangeWindowMode(DX.TRUE);
+         DX.DxLib_Init();
+         DX.SetDrawScreen(DX.DX_SCREEN_BACK);
+     }

    static void Main(string[] args) {
-        // ウィンドウモードで起動するように設定
-        DX.ChangeWindowMode(DX.TRUE);
-        // Dxlib の初期化
-        DX.DxLib_Init();
-        // 描画先を裏画面に設定
-        DX.SetDrawScreen(DX.DX_SCREEN_BACK);
-
        while (DX.ProcessMessage() == 0) {
            // 画面をクリア
            DX.ClearDrawScreen();
            // 文字を描画
            DX.DrawString(100, 100, "Hello World", DX.GetColor(255, 255, 255));
            // 裏画面の内容を表画面に反映
            DX.ScreenFlip();
        }
        DX.DxLib_End();
    }
}
```

#### 解説
> まぁ「コンストラクタ」って単語が出てきたら「クラスをnewした瞬間に実行される関数なんだな～」と、お考えください。

https://wa3.i-3-i.info/word13646.html

**(改善のポイント)**
✅ `Program` のコンストラクタを作ったことで、`Main` がシンプルになった！
✅ 今後、初期化処理を追加するときも、コンストラクタに書けばいいので、管理しやすくなった！

## **変更点 2: ゲームの描画処理を分離したい**
#### **(ここを変更したい！)**
ゲームの **描画処理 (`ClearDrawScreen`, `DrawString`, `ScreenFlip`)** が `Main` に直接書かれています。  
もし今後「別のオブジェクトを描画したい」と思ったら、`Main` を書き換えないといけません。  

#### **(じゃあどうすればいいか？)**
**「ゲームの処理だけをまとめたクラス (`Game`) を作る」**  
`Game.Run()` というメソッドを作成し、描画処理をそこにまとめます。  

#### **(ソースコードの変更)**
```diff csharp:Program.cs
+class Game {
+    public void Run() {
+        while (DX.ProcessMessage() == 0) {
+            DX.ClearDrawScreen();
+            DX.DrawString(100, 100, "Hello World", DX.GetColor(255, 255, 255));
+            DX.ScreenFlip();
+        }
+    }
+}

static class Program {
+    static Game Game;

    static Program() {
        DX.ChangeWindowMode(DX.TRUE);
        DX.DxLib_Init();
        DX.SetDrawScreen(DX.DX_SCREEN_BACK);
    }

    static void Main(string[] args) {
-        while (DX.ProcessMessage() == 0) {
-            // 画面をクリア
-            DX.ClearDrawScreen();
-            // 文字を描画
-            DX.DrawString(100, 100, "Hello World", DX.GetColor(255, 255, 255));
-            // 裏画面の内容を表画面に反映
-            DX.ScreenFlip();
-        }
+        Game = new Game(); // Gameクラスのインスタンスを生成
+        Game.Run();        // インスタンスを介してRun関数を呼び出し
+
        DX.DxLib_End();
    }
}
```

#### 解説
オブジェクト指向におけるクラスは設計書によく例えられます。  
先程の例では、`Game`クラスが設計図に相当し、実際にその設計図をもとにインスタンスを生成しなければ、その設計に基づいた処理は実行されません。

https://wa3.i-3-i.info/word1118.html

`Run`関数は非静的メソッドとして定義されているため、まず`Game`クラスのインスタンスを生成し、それを介して呼び出す必要があります。

https://wa3.i-3-i.info/word11858.html

**(改善のポイント)**
✅ `Game.Run()` に描画処理をまとめたので、描画ロジックを変更するとき `Main` を修正する必要がなくなった！
✅ `Game` クラスを拡張すれば、今後新しいゲーム要素を追加しやすくなる！

## **変更点 3: コードの役割を明確にする**
#### **(ここを変更したい！)**
これまでの変更で `Main` は **「プログラムの流れを制御するだけ」** になりました。  
しかし、ゲーム処理 (`Game.Run()`) は描画だけでなく、**ゲームの進行（状態管理など）も担当する可能性** があります。  

#### **(じゃあどうすればいいか？)**
**「今後の拡張を考えて、Game に更新処理を追加する」**  
まずは `Update()` というメソッドを用意し、処理の流れを明確にします。

#### **(ソースコードの変更)**
```diff csharp:Program.cs
class Game {
+    public void Update() {
+        // 今後のゲームの更新処理 (キャラクターの移動など) をここに追加
+    }

+    public void Render() {
+        DX.ClearDrawScreen();
+        DX.DrawString(100, 100, "Hello World", DX.GetColor(255, 255, 255));
+        DX.ScreenFlip();
+    }

    public void Run() {
        while (DX.ProcessMessage() == 0) {
-            DX.ClearDrawScreen();
-            DX.DrawString(100, 100, "Hello World", DX.GetColor(255, 255, 255));
-            DX.ScreenFlip();
+            Update();
+            Render();
        }
    }
}

static class Program {
    static Game Game;

    static Program() {
        DX.ChangeWindowMode(DX.TRUE);
        DX.DxLib_Init();
        DX.SetDrawScreen(DX.DX_SCREEN_BACK);
    }

    static void Main(string[] args) {
        Game = new Game();
        Game.Run();

        DX.DxLib_End();
    }
}
```

**(改善のポイント)**
- `Update()` を追加し、ゲームの処理の流れを **「更新 → 描画」** に整理！
- もし **キャラクターの動き** や **キー入力処理** を追加したいときは `Update()` に書けばOK！
